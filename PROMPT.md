## 5. Data Model

Exactly these four fields — nothing more:

```csharp
// Models/TodoItem.cs
namespace TodoApp.Web.Models;

public class TodoItem
{
    public int Id { get; set; }
    public string Title { get; set; } = string.Empty;
    public bool IsComplete { get; set; }
    public DateTime CreatedAtUtc { get; set; } = DateTime.UtcNow;
}
```

`Title` must be non-empty/non-whitespace and at most 200 characters. Enforce this in the **service layer** (not only in the UI), so the rule holds regardless of caller.

## 7. Architecture Rules

Blazor Interactive Server components can concurrently touch state across renders and event callbacks, so **do not** register `TodoDbContext` as a plain scoped `DbContext`. Use a context **factory** instead, and have the service create a fresh, short-lived context per operation:

```csharp
// Program.cs
builder.Services.AddDbContextFactory<TodoDbContext>(options =>
    options.UseSqlite(builder.Configuration.GetConnectionString("TodoDb")));
builder.Services.AddScoped<ITodoService, TodoService>();
```

```json
// appsettings.json
{
  "ConnectionStrings": {
    "TodoDb": "Data Source=todo.db"
  }
}
```

`TodoService` takes `IDbContextFactory<TodoDbContext>` in its constructor. Each method creates and disposes its own context:

```csharp
await using var ctx = await _factory.CreateDbContextAsync();
```

Exact `ITodoService` contract — implement all five methods, no more:

```csharp
public interface ITodoService
{
    Task<List<TodoItem>> GetAllAsync();
    Task<TodoItem> AddAsync(string title);
    Task UpdateTitleAsync(int id, string newTitle);
    Task ToggleCompleteAsync(int id);
    Task DeleteAsync(int id);
}
```

`AddAsync` and `UpdateTitleAsync` must throw `ArgumentException` if the title is null/empty/whitespace, or longer than 200 characters (after trimming).

## 8. Functional / UI Requirements

Everything lives in one page, `Components/Pages/Home.razor` at route `/`. Do not split it into child components — this keeps the event-wiring surface small and easy to verify.

The page must have:
- A text input plus an "Add" button to create a new todo. Enter key in the input also submits. Input is cleared after a successful add. Reject empty/whitespace input client-side before calling the service (in addition to the service-layer check).
- Three filter controls — **All / Active / Completed** — backed by a local enum in the component's code, filtering the already-loaded in-memory list (do not re-query the database per filter click).
- One row per todo, showing:
  - A checkbox bound to `IsComplete`. Changing it calls `ToggleCompleteAsync`, then reloads the list.
  - The title as text. Clicking an "Edit" control turns it into an inline textbox with Save/Cancel buttons; Save calls `UpdateTitleAsync`, then reloads.
  - A "Delete" button that calls `DeleteAsync` immediately — no confirmation dialog.

## 10. Testing Requirements

`TodoService` depends on `IDbContextFactory<TodoDbContext>`, not a `DbContext` directly, so tests need a small test double: a private `IDbContextFactory<TodoDbContext>` implementation that wraps a `DbContextOptions<TodoDbContext>` built from an open, in-memory SQLite connection (`Data Source=:memory:`). Because xUnit constructs a fresh instance of the test class for every `[Fact]`, put connection setup (`_connection.Open()`, `context.Database.EnsureCreated()`) in the constructor and `_connection.Dispose()` in `IDisposable.Dispose()` — this gives every test its own isolated database with no shared state and no ordering dependency.

`TodoServiceTests.cs` must include at least these cases:

- Adding a todo persists it with `IsComplete == false` and a populated `CreatedAtUtc`.
- Adding an empty or whitespace title throws `ArgumentException`.
- `GetAllAsync` returns previously added items.
- `ToggleCompleteAsync` flips `IsComplete` on the target item.
- `UpdateTitleAsync` changes the title of the target item.
- `DeleteAsync` removes the target item.

## 12. Out of Scope

Do not add any of the following:

- Authentication, authorization, or user accounts
- A separate REST/minimal API project, a `.Client` WASM project, or PWA support
- Any `TodoItem` fields beyond `Id`, `Title`, `IsComplete`, `CreatedAtUtc` — specifically no `Description`, `Priority`, `DueDate`, `Tags`, `CompletedAtUtc`, sub-tasks, or attachments
- Drag-and-drop reordering
- Third-party UI/component libraries (MudBlazor, Radzen, etc.) — use the template's default Bootstrap CSS only
- Docker files or CI/CD pipeline config
- Localization or theming/dark-mode beyond the template default
- A delete-confirmation modal
- Custom JavaScript interop
- Any logging framework beyond the default `ILogger`

Make sure `.gitignore` excludes `bin/`, `obj/`, and `todo.db`.
